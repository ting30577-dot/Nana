# D3-07 planning-gate evidence (no implementation)

Date: 2026-08-09. This evidence records planning and review only. No T3
capability, export route, external target, or filesystem write was enabled.

## Decomposition

D3-07 is divided into 07-00 entry/security gate, 07-01 typed Approval atomic
writer, 07-02 exact T3 capability contract, 07-03 allow-root and atomic-write
protocol, 07-04 crash/security/projection matrix, and 07-05 scan/repair/joint
exit. The draft is in `docs/d3_07_stage_decomposition_draft.md`.

## First scan and repair

The first scan recorded F07-01 through F07-09 in
`docs/d3_07_first_scan_findings.md`. A Codex-only 07-00 record was then added
in `docs/d3_07_entry_gate_decision_record.md`:

- Action id + ActionHash subject binding: design ACCEPT.

  and result must be all-or-nothing. D3-00 R1 plus the product-owner decision

  T4 `export.publish`/`PublishExport`; it remains unregistered.
- Launcher/CLI user selection plus opaque browser id is product-frozen;
  conservative `effect_unknown` remains a design invariant.
- Unsupported/unknown atomic replace and non-atomic fallback: VETO.
- Remote publish: VETO.
- D3-06 Claude implementation exit and joint 07-00 signature: VETO/pending.

Its third no-edit scan withdrew the earlier consistency claim and recorded

The same repair recorded F07-20 as a new P0. The later product decision freezes
read-only selection checks, atomic Approval/consumption and a durable first-write
fence before the positive probe or any external byte. Before-byte failure is
empty-effect `failed`, proven-cleaned probe effects are recorded, and
unverifiable residue/crash is `effect_unknown`; no fallback/retry exists. This
still needs independent/joint review. No runtime surface changed.

The authority recheck then recorded F07-21 as P0. The product decision now
freezes an existing dedicated empty target on a supported fixed local
filesystem; root/profile/system/Nana/Workspace overlap, reparse/identity alias,
UNC/network/mapped/cloud-sync, collision/change and unverifiable filesystem
targets are rejected. Fixed filename/no overwrite remains mandatory. Joint
security review and implementation evidence are still required.

The later export-subject audit recorded F07-22 through F07-25. The product
decision now freezes the existing producer/Artifact-lineage graph plus snapshot,
the narrow server-derived application request, deterministic system `CancelRun`,
and a public-only exact UTF-8/NFC/LF Markdown renderer with a 4,096-byte ceiling,
fixed digest/template/DRAFT marker and 50 canaries. The closed
Relation Registry cannot directly express an Export Run consuming a Finding or
source Run; the current T2-only `StartRun` writer cannot create the Export Run;
denial/expiry needs a separate idempotent terminalization step; and D3-06 has no
Markdown draft-report Artifact to bind to the ActionHash. The candidate reuses
the existing producer/Artifact-lineage Relations plus a frozen snapshot,
composes existing canonical Command semantics behind a narrowed
`RequestApproval` application request, uses a post-denial deterministic
`CancelRun`, and freezes deterministic report bytes before requesting Approval.
All four remain design-only pending independent/joint verdicts.

The opaque-selection registry audit then recorded F07-26 through F07-31. There
is no durable session/selection row, raw paths may not enter portable canonical
data, Windows identity cannot be proven by string resolution alone, and an
in-memory reservation cannot share an atomic commit with SQLite. The product-
frozen design uses an app-instance registry with a retained directory handle,
no restart rebinding, 60-minute/LocalSession one-Export binding, interactive CLI
selection distinct from harness injection, write-fence-based restart outcomes,
and an explicit reserve→SQLite commit→finalize coordination protocol. It limits raw
path/handle/token/clear identity to process memory, permits only irreversible
non-locating durable commitments, and requires a durable fence before effects.
These are not implementation permissions and require independent/joint review.

The complete product ruling is
`docs/d3_07_plan_aligned_decisions.md`. It closes product-choice ambiguity for
F07-20 through F07-31 without changing the machine flags or enabling writes.
