# v0.3.0-dev D2-01 scheduler gate 证据

## 范围

D2-01 实现持久化 scheduler admission 与 cancellation state gate。它不执行工具、
不 spawn child process、不 consume approvals 或 policy grants、不 publish exports、
不增加 HTTP mutation routes、不构建 React UI、不实现 Tauri/launcher 行为，也不进入
alpha.1 算法工作。

## 协作记录

- Codex 独立结论：D2-01 应是 D2-00 之后、真实 capability process execution 之前的
  第一个 scheduler/cancel 单元。
- Claude review：目标与 non-goals 为 ACCEPT；`max_actions` 仅作为 count-based
  scheduler admission gate 接受，不是完整 budget system。
- Claude follow-up VETO：pending action cancellation 不得复用 `action.completed`；
  D2-01 必须新增 `action.cancelled`。
- Codex 接受该 VETO，并把 `action.cancelled` 实现为 additive event type。由 Run
  transition 取消的 already-claimed/running actions 使用 `action.effect_unknown`。
- 决策记录：`docs/d2_01_decision_record.md`。
- 脱敏 review packet：`docs/claude_d2_01_design_packet_sanitized.md`。

## 已验证行为

- 为 running Run claim 一个 already-authorized action 会在单个 SQLite transaction 中
  完成，并只追加一条 `action.started` Event/outbox row。
- 两个 SQLite connections 竞争 claim 同一个 authorized action 时，恰好一个成功。
- 无效 claim attempt 不会修改状态，也不会追加 Events。
- `max_actions` 是 count-only scheduler gate。耗尽时，claim 将 Run 转为
  `budget_exceeded`，追加 `run.budget_exceeded`，且不启动新的 Action。
- 取消没有 running Action 的 non-terminal Run 会直接收敛为 `cancelled`；有 running
  Action 时先进入 `paused/cancel_requested`，pending Action 取消，running Action 保持
  running，直到 executor 完成进程树、Receipt 与预算结算后才进入 `cancelled`；终止
  不可验证则 `orphaned`。
- 对 terminal Runs 再次 cancel 是幂等的，不会追加重复 Events。
- claim/cancel race 测试留下单一 terminal Run state，并且 Run cancellation 后不会
  遗留 running Action。
