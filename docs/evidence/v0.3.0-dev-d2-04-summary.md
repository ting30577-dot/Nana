# v0.3.0-dev D2-04 证据摘要

D2-04 实现 `python.unittest.locked` 的受信、冻结、极窄本地执行器；它不是通用不可信代码沙箱。

关键边界：

- 只 claim 已 authorized 且 capability id/version/digest 与 built-in registry 一致的 Action；
- args Artifact 在解析前校验 persisted size、授权 artifact budget、blob hash、canonical args hash 与 frozen test id；
- registry read roots 固定为 `project:source` / `project:tests`，write/network/env 均为空，process target 固定为 `builtin:python.unittest.locked`；
- worker 在测试 import 前安装 audit guard，拒绝项目越界读取、全部写入、网络和子进程；
- parent 使用 argv、`shell=False`、空环境和 `stdin=DEVNULL`；
- Windows worker 以 `CREATE_SUSPENDED` 创建，先绑定 kill-on-close Job Object 再 Resume；绑定、恢复、终止或 5 秒退出验证失败均 fail closed；
- timeout、运行中取消、输出截断和 runner 异常都写 `effect_unknown` Receipt 并完成预算结算；
- stdout/stderr 共享一个硬字节上限；Receipt 保存授权来源、授权/观察 effects、资源使用和结果。

补审发现：

- 30 个真实取消 fixture 证明旧 `taskkill /T` 路径 30/30 无法验证树退出；Claude 又发现 Popen 后绑定的理论窗口。最终 30 个 fixture 都在 worker guard 前启动真实孙进程，并证明 suspended-bind-resume Job 在 5 秒内回收整树。
- frozen unittest 不产生 scratch Artifact，registry `write_roots` 已收窄为空；未来若需产物，必须新增 capability contract/digest 和 resolver。

聚焦验证：`tests.test_d2_locked_executor`、`tests.test_d2_security_corpus`、`tests.test_d2_security_matrices` 均通过。Claude 二审对 F4/F5/F6/F7 全部 ACCEPT；D2-04 最终共同 ACCEPT。
