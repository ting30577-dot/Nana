# v0.3.0-dev D3 page-token session binding evidence — 2026-08-10

Bootstrap section-token HMAC verification is bound to the active runtime
LocalSession secret. A token issued under one session secret is rejected by a
read model using another secret, even when the database and section are the
same. The checked-in runtime constructs the read model with the LocalSession
token rather than a shared static secret.

Verification:

- Read-model tests cover cross-session token rejection in addition to signature
  tampering, canonical Base64URL, section binding, and watermark/offset bounds.
- Runtime authority integration now obtains a 413 bootstrap page token under
  one LocalSession and proves that replaying it through a second runtime
  session returns structured `400 E_PAGE_TOKEN`.
- The targeted integration test passes; the full strict D3 boundary remains
  123 tests with 2 declared platform skips.
- No session credential is serialized into the token payload; only the HMAC
  protects the opaque payload.
- No mutation, authorization, capability, export, or filesystem behavior
  changed; D3-07 remains unresolved.
