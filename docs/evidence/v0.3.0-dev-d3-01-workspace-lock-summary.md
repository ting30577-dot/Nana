# D3-01 Workspace lock lifecycle evidence

Date: 2026-08-01

Joint exit decision: Codex `ACCEPT`; Claude `ACCEPT`; D3-01 `ACCEPT`.

## Scope

This slice proves only canonical Workspace ownership and artifact
reconciliation lifecycle. It does not open HTTP mutation routes, React
production navigation, or external T3 export.

## Implementation

- `nana_sidecar/storage/workspace_lock.py`
- `tests/test_d3_workspace_lock.py`

Startup order is:

`resolved database identity -> OS-exclusive Workspace lock -> writable SQLite/migrations -> real D1 ArtifactReconciler -> ready`

Shutdown order is:

`draining -> writer quiescence -> SQLite close -> OS lock release -> closed`

The OS handle is the sole ownership authority; schema v6 has no persisted
Workspace-lock row or marker. Database and lock identities are checked against
the canonical parent, and the constructor exposes no reconciliation or lock
path override that could bypass those invariants. Startup/close/quiescence
failures remain fail-closed and retain ownership where SQLite may still be
usable.

Failure ownership is explicit:

| Failure | Ownership result |
|---|---|
| Startup failure with no connection, or successful cleanup close | release lock |
| Startup cleanup cannot close SQLite | retain lock; `startup_close_failed` |
| Writer quiescence fails | retain connection and lock; `drain_failed` |
| Shutdown cannot close SQLite | retain lock; `close_failed` |
| SQLite closed but OS release reports failure | do not claim closed; `lock_release_failed` |
| Reconciliation fails and cleanup close succeeds | release lock; later restart may reconcile |

## Boundary

The Windows exclusive-handle path was exercised here. The POSIX fallback is
implemented but was not executed in this Windows environment, so it is not
claimed as independently verified. Launcher packaging, Local Web bootstrap
token exchange, Tauri, and parallel Workspace owners remain outside this
slice. Real mutation serving remains gated on the remaining D3 runtime,
projection, and UI work. External T3 export remains disabled under the D3-00
joint decision.

The process-crash test denies a contender while the child is alive, then calls
`kill()` and waits for confirmed termination before attempting recovery; it
does not rely on a fixed sleep to infer handle release.

The real Windows symlink integration test remains privilege-skipped. Its
rejection decision branch is covered by a passing deterministic identity-probe
test; a privileged CI execution is a non-blocking follow-up required before
real mutation serving is enabled.

The pre-existing PySide6 shutdown diagnostic still reports one uncollectable
object after the otherwise successful full Python suite. D3-01 focused strict
tests are clean. Per the D2 handoff, this remains non-blocking now but must be
shown unrelated to the D3 process/handle/write path before mutation serving.
