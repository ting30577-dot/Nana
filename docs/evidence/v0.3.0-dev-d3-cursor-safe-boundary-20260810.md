# D3 browser cursor safe-integer boundary evidence — 2026-08-10

SQLite permits signed 64-bit Event IDs, while the current browser projection
stores cursors as JavaScript numbers. The existing implementation therefore
fails closed when an Event ID or bootstrap high-water exceeds
`Number.MAX_SAFE_INTEGER`; it never rounds the ID and continues projection.
The sidecar still validates the HTTP `Last-Event-ID` against the SQLite range,
so this is an explicit browser-consumption ceiling, not a claim that SQLite
itself has a smaller key range.

Vitest now covers both sides: an unsafe SSE Event ID is rejected before cursor
advance, and an unsafe bootstrap high-water is rejected as malformed canonical
state. Sparse safe IDs remain supported. No cursor, route, mutation,
authorization, capability, or filesystem behavior was widened.
