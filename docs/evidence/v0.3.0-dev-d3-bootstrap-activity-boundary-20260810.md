# D3 bootstrap Activity cursor-boundary evidence — 2026-08-10

The browser projection now validates that canonical bootstrap Activity rows
are strictly increasing by Event ID and remain at or below the snapshot's
same-read `high_water_event_id`. Duplicate, descending, and post-snapshot
Activity rows fail closed with `E_BOOTSTRAP_ACTIVITY` before the projection
becomes usable. Canonical collection maps likewise reject duplicate IDs with
`E_BOOTSTRAP_ID` instead of silently replacing an earlier row.

The boundary is compatible with the bounded server Activity window: the server
returns an ascending suffix of committed Events, while the client does not
assume integer continuity or require the suffix to begin at Event ID one.
Vitest covers the three Activity cases and duplicate collection IDs. TypeScript check, projection self-test,
Vite build, and the 15-test authenticated read-only browser suite pass.
No route, mutation, authorization, capability, cursor transport, or filesystem
behavior was widened.
