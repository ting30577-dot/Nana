# Nana · 项目全景

> **当前状态**：v0.2.0-alpha · 新研究骨架成立，处于早期验证阶段
> **产品定义**：以算法与方法为核心，借助 AI 将外部研究成果转化为自身能力的个人研究成长系统。
> **平台策略**：本地桌面优先，核心逻辑与界面分离，Web 客户端按真实需求后置。

## 一、方向决策

Nana 最初由算法可视化和论文管理两个想法合并而来。早期版本实现了算法动画与 LeetCode 记录，但“学生学习工作台”无法解释项目真正想长期解决的问题。

新的判断标准是：

> Nana 是否帮助用户吸收、理解、验证、迁移并内化一种方法？

因此：

- 算法继续作为重要核心和首个验证场；
- 论文、项目和代码是方法的来源，不是最终资产；
- AI 首先是共同阅读者、解释者、质疑者和实验助手；
- 研究方向暂不固定，等真实经历使方向稳定后再加入领域模块；
- 外部项目可以学习，但功能清单不能直接成为 Nana 的路线图。

## 二、产品边界

### Nana 要做

- 从大量候选资料中选择值得深入的论文或项目；
- 区分来源事实、Research Lens、AI 推断和个人判断；
- 将方法拆解到能够实现、比较和验证的程度；
- 保存证据、实验、失败原因和可迁移的方法卡片；
- 随用户成长加载不同领域知识，而不是绑定单一方向。

### Nana 不做

- 面向零基础用户的通用算法教程；
- 只展示动画的算法演示库；
- 只保存 PDF、标签和摘要的论文仓库；
- 没有证据边界的通用聊天窗口；
- 当前阶段的自治研究 Agent；
- 为了显得完整而复制其他科研平台的全部基础设施；
- 当前阶段的 Web 客户端或多人云平台。

## 三、研究闭环

```text
真实问题
→ 候选论文、项目和代码
→ 选择性导入
→ AI 中性整理与证据定位
→ 方法拆解和比较
→ 最小实现、实验或反例
→ 个人判断
→ 方法卡片
```

一次精读的最小成果是：

1. 一个明确问题；
2. 一张方法卡片；
3. 若干条可定位证据；
4. 一次实现、比较或反例；
5. 一条个人判断和下一步行动。

## 四、核心对象

| 对象 | 含义 |
| --- | --- |
| Research Thread | 围绕一个真实问题组织来源、方法、证据、实验和判断的工作上下文 |
| Source | 论文、项目、代码、数据集、博客或题目案例；`case` 是 Source 的类型，不是独立对象 |
| Method | 可迁移的算法思想、机制或研究策略 |
| Claim | 来源明确提出的结论 |
| Evidence | 原文、代码位置或实验数据 |
| Experiment | 复现、比较、验证或反例 |
| Insight | 用户认可、修正或否定后的个人判断 |

论文不是中心实体。可解释、可实现、可验证和可迁移的方法才是长期资产。“方法卡片”是一个 Method 连同关联 Claim、Evidence、Experiment 和 Insight 的界面表达，不增加另一套重复数据。Research Lens 不属于 `v0.2.x`；稳定闭环之后只有满足真实需求、来源边界和评测条件时才单独立项。

## 五、当前 Alpha 骨架

现有代码已经进入 `v0.2.0-alpha`。旧产品入口已经退出运行时，七类研究对象、遗留数据安全归档和方法实验室最小骨架已经成立。版本划定仍必须区分“仓库里暂时存在”“底层可以复用”和“产品继续认可”；三者不能互相替代。

### 可复用基础

- 算法状态生成、动画绘制和界面交互已经有分层；
- 滑动窗口、双指针、前缀和、二分、单调栈等模式已有基础步骤；
- SQLite、本地测试和 Windows 打包链路已经可用；
- 暖色浅色主题已经替换旧的深色科技感。

### 遗留处置

| 遗留内容 | 决策 | 可复用部分 |
| --- | --- | --- |
| 手工刷题记录与统计 | 从产品路线和运行入口移除，不做隐藏版或改名版 | 无；若有真实用户数据，只提供迁移/导出 |
| 旧算法工作台页面 | 整体退役，不作为新算法模块的页面骨架 | 算法函数、状态轨迹、画布、播放控制、测试 |
| LeetCode 关联题列表 | 取消内容中心地位 | 有需要的题目可作为 `case` 类型的 Source 被引用 |
| SQLite 与打包链路 | 保留并重新服务研究对象 | 连接管理、迁移机制、测试与构建脚本 |

算法依然是重要大板块，但不再等同于“刷题 + 模式动画”。新结构以研究线程为上下文：

```text
问题或来源
→ 候选方法
→ 关键假设 / 不变量
→ 最小实现
→ 测试、反例与比较
→ 证据化结论
→ 方法卡片与个人判断
```

算法题只是来源或验证案例之一；可视化只是实验结果的一种视图。Nana 不要求用户维护“做过哪些题”，而是保留哪些判断经过了什么验证。

## 六、当前技术结构

| 层 | 当前技术 | 状态 |
| --- | --- | --- |
| 桌面 UI | PySide6 | 已实现 |
| 算法可视化 | Matplotlib | 已实现 |
| 本地存储 | SQLite | 已实现 |
| Windows 打包 | PyInstaller | 已实现 |
| Nana Core | 独立领域对象和服务层 | 待建立 |
| AI 接入 | 可替换模型供应商接口 | 待建立 |
| 论文/项目处理 | 选择性导入、解析和证据定位 | 待建立 |
| Web 客户端 | 复用 Nana Core | 非当前范围 |

后续代码应逐步形成：

```text
nana_core/
├── research/          # 来源、方法、证据、实验、洞见
├── ai/                # 模型供应商、提示、评测
└── storage/           # 数据库和本地文件

ui/
├── research/          # 研究线程、来源与精读界面
├── lab/               # 方法实现、测试、比较与可选可视化
└── settings/          # 模型、数据和主题设置
```

现有目录在需求验证前不为追求形式而提前重构。

## 七、发展阶段

路线按能力门槛划分，不再按旧功能表和固定日期排期。

### 阶段 A：切断旧产品形态并建立新骨架

- 统一项目文档与产品定义；
- 默认采用暖色浅色主题；
- 修复算法边界和数据库测试问题；
- 从运行入口移除刷题账本和旧算法工作台；
- 建立 Research Thread、Source、Claim、Evidence、Method、Experiment、Insight 的最小结构；
- 将可复用算法执行与绘图能力下沉为方法实验室工具；
- 保持测试、打包和本地数据可靠。

完成标志：启动 Nana 时已经看不到被否定的旧产品结构，算法可以在研究线程中完成一次无 AI 的最小验证。

### 阶段 B：验证一次 AI 精读闭环

- 支持一种模型供应商；
- 选择性导入一篇论文或一个项目，并保存其版本边界；
- 生成中性结构化整理；
- 按页码/章节或 commit/文件/符号定位证据，并由用户核对；
- 保存用户修改和个人判断；
- 形成一张方法卡片；
- 让方法实验室承接精读后的边界用例、最小实现和实验验证。

完成标志：真实资料可以从“导入”走到“个人方法沉淀”。

### 阶段 C：形成方法库

- 比较相近方法；
- 连接论文、项目、算法实现和实验；
- 逐步形成领域术语、方法谱系和评测问题；
- 根据失败记录决定是否增加模型路由。

完成标志：一次精读的结果可以在另一个问题中被复用。

### 阶段 D：方向稳定后的领域化

- 根据真实研究方向建立领域包；
- 增加数据集、指标、基线和领域失败模式；
- 领域化不自动引入 Research Lens；二者分别按真实需求立项；
- 有足够高质量数据后，再评估微调或本地专用模型。

## 八、视觉与交互

Nana 的默认气质是温暖、轻盈、安静和适合长时间阅读：

- 米白、浅棕、沙色、暖灰作为主要背景；
- 浅紫、鼠尾草绿、陶土色作为状态和强调色；
- 用留白、排版、边框和明度建立信息层级；
- 深色模式可以后续提供，但不以深蓝、深紫塑造默认科技感；
- 界面更像个人研究书桌，而不是实验室控制台。

## 九、质量门槛

每个新增能力至少满足：

1. 解决真实使用问题；
2. 不把 AI 推断伪装成来源事实；
3. 核心逻辑可独立测试；
4. 数据能够本地持久化并可追溯；
5. Windows 打包版本可以启动；
6. 不因为外部项目拥有某功能就默认加入；
7. 能解释它如何服务吸收、理解、验证、迁移或内化。

## 十、版本划定

版本号从现在起按能力边界划分，不再沿用旧的功能堆叠路线。当前代码处于 `v0.2.0-alpha`；`alpha`、`beta`、`rc` 都属于重新定义后的 `v0.2.0` 研究闭环验证线。

| 版本 | 对应阶段 | 完成标志 |
| --- | --- | --- |
| `v0.2.0-dev` | 已结束的迁移态 | 遗留代码可以暂存，但不发布，也不把旧页面列为产品能力。 |
| `v0.2.0-alpha` | 当前：阶段 A | 旧刷题与旧算法页面退出运行入口；Research Thread、Source、Claim、Evidence、Method、Experiment、Insight、遗留数据安全归档与方法实验室骨架成立；一个真实算法问题可以完成无 AI 的最小研究验证。 |
| `v0.2.0-beta` | 阶段 B | 单篇论文或单个项目可以完成选择性导入、AI 中性整理、证据定位与用户核对、用户修正、方法卡片和最小实验。 |
| `v0.2.0-rc` | 阶段 B 收尾 | 功能冻结，只修复闭环完整性、数据可靠性、隐私边界、打包和交互。 |
| `v0.2.0` | 阶段 B 完成 | 第一条单资料研究闭环可以反复使用，产物可追溯、可修改、可再次进入实验。 |
| `v0.3.0` | 阶段 C | 跨来源比较和方法复用成立；该版本与旧路线的“论文库 v0.3”没有继承关系。 |

阶段 D 不预设版本号。Research Lens 在 `v0.2.x` 不做，稳定闭环之后也不自动成为 `v0.3.0` 或领域包的组成部分。研究方向、真实使用样本和隐私边界没有稳定之前，不承诺领域包、模型训练/微调或 Web。任何阶段都不把刷题清单、更多动画数量或其他项目的功能清单当成完成标准。

## 十一、旧版本状态

- `v0.1.0` 作为冻结的历史原型保留，不删除历史，也不作为新产品能力基线；
- 旧 `v0.2` 方案未发布，其旧功能定义作废；仓库已有 `v0.1.0` 历史标签，新的研究线已经从迁移态进入重新定义后的 `v0.2.0-alpha`；
- 原定的 `v0.3 论文库`、`v0.4 ML 可视化`、`v0.5 知识图谱`、`v1.0 Web 接口` 路线全部失效；
- 新版本只依据真实研究闭环的验证结果推进。
