# D3-08A Codex-only implementation exit

Date: 2026-08-11  
Decision: **ACCEPT**

## Scope accepted

D3-08A adds the narrow browser command workbench for the already-typed D3
journey: create Project and Inquiry, register frozen provenance, propose and
revise a Plan, start or cancel the fixed `python.unittest.locked` Run, and
commit a Finding draft. The browser sends only the curated Journey contracts.
It does not expose Approval, export, capability selection, authorization,
paths, arbitrary commands, shell, Python, or filesystem bytes.

The UI keeps editable text as a draft. A command response is only an accepted
request: the store performs an authenticated canonical bootstrap before it
reports reconciliation. SSE continues to use `fetch` plus `ReadableStream`.
The command channel is default-deny from the authenticated handshake, is
single-flight, and reuses the exact command ID after response loss.

## Implementation evidence

- `nana_web/src/JourneyWorkbench.tsx`: six-stage typed workbench with
  canonical eligibility guards and no Approval/export surface.
- `nana_web/src/store.ts`: authenticated handshake, exact allow-list,
  single-flight command transport, data-safe structured errors, conflict
  refresh, response-loss recovery and canonical reconciliation.
- `nana_web/src/projection.ts`: canonical Project collection and event-key
  parity for `relation.created` and budget events.
- `nana_sidecar/read_models.py`: field-whitelisted canonical Project rows.
- `scripts/run_d3_mutation_ui.py` and
  `nana_web/playwright.mutation.config.ts`: explicit disposable test harness;
  it does not masquerade as launcher selection or production authority.
- `nana_web/tests/mutation/journey.spec.ts`: real Chromium success and cancel
  journeys, conflict, response loss, double-submit, exact command bodies,
  reflow and accessibility.
